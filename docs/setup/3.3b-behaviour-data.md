# Task 3.3b: Behaviour data (how customers use the bot)

**Time:** about 20 minutes. **Cost:** ₪0 (fits in Supabase's free plan).
**Do it on:** GitHub, the Mac Mini and your phone.

**Why:** task 3.3 records every step of every order. This task adds what you need to understand **how customers behave** and **where they get stuck**, so the first real customers' data is complete (it can't be recorded afterwards). A dashboard comes later; for now the data is ready in tables you can download.

**What's new:**
1. **Where the customer came from:** a short code in our WhatsApp links (e.g. `#fb1`), and the ad's ID when someone taps a Meta "click to WhatsApp" ad.
2. **Test mark:** orders from your phone and the family's phones are marked as tests, so they never mix with real customers.
3. **Every message the customer sends:** its kind (button, text, photo…), which button, whether it changed anything. For a text only its **length**, never the words. Typing where a button was expected = a "confused" sign.
4. **Delivered / read** for every bot message, with the message's name (e.g. `photos_count`).
5. **The album page:** opened or not, how many times, how many devices, phone or computer, how far they scrolled. Your own visits (from your approval message) are marked "owner".
6. **The bot's version** on every row, to compare before and after a change.
7. **An anonymous customer key:** the phone number scrambled with a secret. The same customer always gets the same key, so repeat customers can be counted even after old orders are cleaned up, but the key can't be turned back into the number.
8. **Ready-made views** (tables you can download): funnel, drop-off, friction, weekly trends, customers, album page visits.
9. **An event dictionary:** [docs/data/events.md](../data/events.md) explains every event name.

🔒 Still **never** recorded: photos, what customers type, names, addresses, phone numbers. The privacy page now has one line saying we measure how the service is used, in numbers only.

> **Words you'll see**
> - **Funnel:** how many orders reached each stage (started → chose a design → … → paid). The stage with the biggest drop is where to improve first.
> - **Source code:** a short English code at the end of the ready-made first message in our links, like `#fb1`. You choose it.
> - **wa.me link:** a link that opens WhatsApp with a message to us already typed. The customer only taps Send.

## Step 2: Add the family's test phones to `.env` on the Mac

Your own phone (`OWNER_PHONE`) is marked as a test by itself. Add the family phones you test with (for example your wife's).

1. On the Mac, in Terminal:

```bash
cd ~/pashut-book && nano .env
```

2. Go to the end and add these two lines (your numbers, any form, separated by commas):

```

BOT_PHONE=
```

`BOT_PHONE` = the bot's own WhatsApp number (the one customers write to; for now the Meta test number). It's only used to make links (step 5).

3. Save: **Ctrl+O**, **Enter**, then **Ctrl+X**.

## Step 4: Keep a copy of the customer-key secret

On its first start, the bot made a secret and added it to `.env` by itself (`CUSTOMER_KEY_SECRET`). It turns phone numbers into anonymous keys. **If it changes or is lost, every customer gets a new key and repeat customers can't be counted any more.** Show it:

```bash
grep CUSTOMER_KEY_SECRET ~/pashut-book/.env
```

Copy the line into your password manager (or a private note). Never put it on GitHub or in a chat. When the bot moves to another computer, copy this line into the new `.env`.

## Step 5: Links with a source code

Every place you share the bot (a post, a WhatsApp group, a flyer…) gets its **own number**, so you'll see which one brings customers. Make a link on the Mac:

```bash
cd ~/pashut-book && python3 server/source_link.py 101
```

It prints a link like `https://wa.me/972…?text=…`. Opening it starts WhatsApp with "שלום! אשמח להכין אלבום תמונות #101" ready to send. The customer sees the number (a link can't hide it), but it means nothing to them. Invisible marks keep it showing as `#101`, not `101#`.

**The numbers** (owner's choice, Nov 26, 2026): the **first digit is the channel**, the rest counts the posts or groups. Use 3 digits.

| Number | Where |
|---|---|
| 101, 102, 103… | Facebook posts (your own or in Facebook groups) and Facebook ads with a plain link |
| 201, 202, 203… | WhatsApp groups (one number per group) |
| 301, 302… | Instagram posts, stories, the link in your profile |
| 401… | LinkedIn |
| 501… | Printed flyers (a QR code of the link) |
| 601 | Friends and family |
| 701 | The website pashutbook.com |

**Paid Facebook / Instagram ads with a "Send WhatsApp message" button need no number:** Meta tells the bot which ad was clicked (source `ad`), and the customer's message stays clean.

Keep a list (a note or a tab in the ROI sheet) of what each number is, with the date and, for ads, the cost. Then you can compare money spent with paid albums for each number. (Codes with letters, like `fb1`, still work too.)

## Step 6: Test it with one order

1. Make a test link: `python3 server/source_link.py 999` (999 = test), and send it to yourself (e.g. in WhatsApp "Message yourself").
2. From your test phone, tap the link and send the message. Do a short order: design, cover photo, a few photos, "סיימתי לשלוח", a title. Once on purpose, **type something instead of tapping a button** (e.g. "קלאסי" when asked to choose a design).
3. When the album link arrives, open it, scroll to the end, then close it.
4. On the Mac:

```bash
cd ~/pashut-book && python3 server/check_supabase.py --history --funnel
```

You should see, in the newest order's moments: `source 999`, `message_in …` rows, `message_out …` with names like `welcome`, `message_delivered` / `message_read`, `album_opened phone`, `album_seen`. Under **Funnel (tests)** your order is counted.

5. In Supabase (Table Editor), look at the views `funnel`, `friction` (your typed message shows as `confused` 1), `album_page_visits` and `order_stages` (columns `test` = true, `source` = 999, `version`).

## Downloading the data

Supabase → **Table Editor** → choose a view (e.g. `funnel`, `drop_off`, `friction`, `weekly_trends`, `customers`, `album_page_visits`) → **Export** → **Export to CSV**. Open it in Google Sheets. To see real customers only, filter `who` = `customers`. What each column and event means: [docs/data/events.md](../data/events.md).

## If something goes wrong

- **The log says "the 3.3b columns are missing":** the SQL wasn't run on this database. Run `supabase/3.3b-behaviour-data.sql` (step 1). Until then the history is saved without the new columns.
- **No `message_read` rows:** the customer turned off read receipts in WhatsApp (Settings → Privacy). Then only "delivered" comes. Messages sent before a bot restart are not followed either.
- **No `album_opened` rows:** the page reports itself only from a browser with JavaScript (all phones have it). Check that the bot was updated (step 3).
- **No `source` row:** the customer deleted the `#code` before sending. Nothing to do; it happens.
