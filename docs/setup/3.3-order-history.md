# Task 3.3: Order history (every step of every order, in Supabase)

**Time:** about 10 minutes. **Cost:** ₪0 (it fits easily in Supabase's free plan).
**Do it on:** Supabase (in the browser), the Mac Mini and your phone.

**Why:** you want to study the data later and improve the process (CLAUDE.md rule 10). From now on the bot writes down **every moment of every order, with its time**: when it started, each step, each photo saved, the album built, each change, "love it", your approval, the address, the payment.

**What gets recorded:** only **numbers and short codes** (how many, how big, how long, which step, which design, which problem).
🔒 **Never** photos, never what the customer typed (title, name, address, messages), never phone numbers. The order's own row in `orders` has the customer details; the history only points to it.

> **Words you'll see**
> - **Table:** like one sheet in a spreadsheet. This task adds a table called `order_events`: one row per moment.
> - **View:** a ready-made, read-only table that Supabase builds from other tables every time you open it. This task adds two: `order_history` (the moments, easy to read) and `order_summary` (one row per order).
> - **CSV:** a simple file of rows and columns that Google Sheets and Excel open.

## Step 1: Add the history table in Supabase (once)

1. Open https://supabase.com/dashboard → the project **pashut-book**.
2. On the left: **SQL Editor** → **New query**.
3. On GitHub (or on the Mac), open `supabase/3.3-order-history.sql`, copy **all** of it, paste it in, and tap **Run**.
4. It should say **"Success. No rows returned"**. (Running it twice is harmless.)

If you skip this step, the bot still works normally; it just writes a warning in its log ("Order history not saved … Did you run supabase/3.3-order-history.sql?") and records nothing.

## Step 2: Update the bot on the Mac

The Mac gets new code only from `main`, so first merge this task's pull request on GitHub. Then, on the Mac, in Terminal:

```bash
cd ~/pashut-book && git pull
```

```bash
cd ~/pashut-book && bash deploy/mac/install-bot-service.sh
```

(The second line restarts the bot so it uses the new code.)

## Step 3: Test it with one order

1. From your test phone, make a short order: a design, a cover photo, a few photos, "סיימתי לשלוח", a title. Wait for the album link, change something (for example the title), then tap **😍 אהבתי!**, approve it on your phone, fill in the shipping details, and tap **💰 התקבל תשלום**.
2. On the Mac:

```bash
cd ~/pashut-book && python3 server/check_supabase.py --history
```

You should see the newest order's moments, one per line, with the time from the start (minutes:seconds). For example:

```
  +  0:00  order_started   (step new, 0 photos)
  +  0:04  step design   (step design, 0 photos)
  +  0:31  photo_saved jpeg 1   (step -, 0 photos)
  ...
  + 14:02  album_built classic 20   (step done, 41 photos)
  ...
  + 31:40  step paid   (step paid, 41 photos)
```

✅ **Done when:** every step of the test order is there with its time, and it downloads as a CSV (step 4).

## Step 4: Download as a CSV (any time)

1. Supabase → **Table Editor** (on the left).
2. Choose one:
   - **`order_summary`**: one row per order. Best for a first look: design, photos, pages, how many changes, how many minutes to the summary / to the album link / to "love it" / for your approval / to pay, price, city.
   - **`order_history`**: every moment of every order, each order's rows together, with `seconds_from_start` and `seconds_since_previous`.
   - (`order_events` is the raw table behind them.)
3. Top right: **Export** → **Export to CSV** (if you don't see it, click the small **⋯** or the "Export" button next to the filters). The file downloads.
4. Open it in Google Sheets: **File → Import → Upload**.

Tip: in `order_history`, filter the `event` column to see one kind of moment across all orders (for example `album_built` or `cover_checked`).

## What each row means

Each row of `order_history` has:

| Column | Meaning |
|---|---|
| `order_code` | The order's first 8 characters (the same code as in the bot's log and your 🔧 messages) |
| `created_at` | When it happened |
| `event` | What happened (list below) |
| `detail` | A short code: the new step, the problem, the design… |
| `count` | The main number: a photo's number, the page count, how many times… |
| `step` | Where the customer was in the conversation at that moment |
| `photos` | How many photos the order had then |
| `seconds_from_start`, `seconds_since_previous` | Waiting times |
| `info` | More numbers (for example the photo's size in KB, seconds to build) |

The main events:

| Event | When | Numbers |
|---|---|---|
| `order_started` | A new order | |
| `step` | The customer moved to another step (`detail` = the new step; `info` = where from) | |
| `photo_saved` | One photo was saved | `count` = its number; `info`: size in KB, long side in pixels, sent without HD?, tries, seconds |
| `photo_failed` | A photo could not be saved | `detail` = too_big / error / database |
| `photos_arrived` | Photos stopped arriving | `count` = photos; `info`: how many with / without HD |
| `counted` | The "we got X photos" message | `count` = X |
| `cover_check`, `cover_checked`, `cover_problem`, `cover_photo`, `cover_kept` | The cover photo: being checked, the result (`detail` = ok / small / blurry / low / shape; `info.dpi`), accepted, kept anyway | |
| `hd_asked`, `hd_early`, `photos_deleted_for_hd`, `resent_from` | The "resend in HD" question and a resend | |
| `album_checked`, `album_built`, `album_failed` | The album: photos used, left out and why, pages (`count`), photos on full pages, seconds | |
| `previews_sent` | The album link was sent | |
| `changing` | A change started from the list (`detail` = title / design / cover / photos / photo) | |
| `used_title`, `used_design`, `used_cover`, `used_photos`, `used_photo` | A change was made (`count` = how many times so far, limit 5) | |
| `removed`, `replaced` | A photo removed / replaced (`detail` = its number, or old:new) | |
| `preview_ok` | The customer tapped "😍 אהבתי!" | |
| `owner_asked` | You were asked to approve | `info`: problems, warnings, notes, seconds to make the print files |
| `approved`, `owner_problem`, `owner_wrote` | Your answer, and a message you wrote (only its length) | |
| `owner_msgs`, `help_wait` | The customer wrote to you (`count` = today's number), asked for help | |
| `payment_wait`, `paid` | Waiting for payment, paid | |
| `new_album`, `new_album_limit` | The customer started over (`detail` = cancelled / kept), or hit the daily limit | |
| (others) | Other moments use the bot's own note names (`confirmed`, `cover_asked`, `after_previews`…); all are short codes | |

**Not yet recorded:** printed, sent and delivered. They come with the printing and shipping tasks. What only you know (your minutes, where the customer came from, the real print cost) stays in the tracking sheet (task S.6).

## How big will it get?

About 150–250 rows per order (most are `photo_saved`), roughly 50 KB. 1,000 orders ≈ 50 MB, well inside the free plan's 500 MB database. The history is **not** deleted with the photos (task 3.4), so the data stays for study.

## If something goes wrong

- **`check_supabase.py --history` says "Did you run supabase/3.3-order-history.sql?"** → do step 1.
- **"nothing yet"** → the history starts with orders made after the update. Make a new test order.
- **The bot's log says "Order history row … not saved"** → Supabase was unreachable for a moment; that one row is missing. The customer noticed nothing.
