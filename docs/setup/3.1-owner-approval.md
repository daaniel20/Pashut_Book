# Task 3.1: You approve every album on WhatsApp

**Time:** about 10 minutes. **Cost:** ₪0.
**Do it on:** the Mac Mini and your phone.

**Why:** you check every album before it's printed. Now the bot brings each album to your own WhatsApp, with buttons, so you can approve it from anywhere.

**What you get at the end:**
1. A customer taps **😍 אהבתי!** on their album. They get: "…עכשיו אנחנו עוברים על האלבום בעצמנו, בדיקה אחרונה לפני ההדפסה…"
2. The bot makes the **print files** (the same as `album/print_pdf.py`) and checks them.
3. **You** get, on your WhatsApp (messages for you start with 🔧):
   - the cover with a **📖 לצפייה באלבום** button (the same page the customer saw), the order number, the last 3 digits of the customer's phone, pages, photos, design, title, and anything worth checking (❌ a photo that would print blurry, ⚠️ a photo a little soft up close, 📝 notes such as "the cover photo was shown smaller"),
   - buttons **[✅ לאשר] [⚠️ יש בעיה]**.
4. **✅ לאשר** → the customer gets "✅ בדקנו את האלבום שלכם, והוא מוכן להדפסה! נחזור אליכם… עם פרטי התשלום והמשלוח." You get the place of the print files on the Mac.
5. **⚠️ יש בעיה** → the bot asks you to type a short message. It sends it to the customer **as is**, with a **[✏️ לשנות משהו]** button (title, design, cover photo, add photos). Type **ביטול** to send nothing. The album stays waiting; you can still tap ✅ לאשר later on the same message.
6. **The customer writes back** (anything typed after "love it") → it comes to you with **[💬 לענות] [✅ לאשר]**.
7. **The customer changes something** → the album is built again and the old buttons stop working ("האלבום הזה השתנה מאז"). You get a new request when they love the new version.

> **Decision in this task:** you approve **right after the customer's "love it", before payment** (task 3.2). So a customer never pays for an album that has a problem, and there's nothing to refund. (README's customer journey was updated.)

> **Words you'll see**
> - **24-hour window:** WhatsApp lets a business send free messages only to people who wrote to it in the last 24 hours. This is true for **you** too. See "Good to know".

## Step 1: Get the new code

```bash
cd ~/pashut-book && git pull
```

## Step 2: Add your number to `.env`

`.env` is the private settings file on the Mac (never on GitHub). Open it:

```bash
open -e ~/pashut-book/.env
```

Add this line at the end, with **your own** WhatsApp number (the phone that is registered on the test number), then save:

```
OWNER_PHONE=050-1234567
```

Any form works (`050-1234567`, `+972 50 123 4567`, `972501234567`).

## Step 3: Restart the bot

```bash
cd ~/pashut-book && bash deploy/mac/install-bot-service.sh
```

## Step 4: Try it on your phone

Your phone is both the "customer" and the "owner" here, and that's fine: only the 🔧 buttons, the word **אישורים**, and the message you type after "⚠️ יש בעיה" go to the owner part; everything else is your normal test conversation.

1. Make a small album as usual (or use the one you have) and wait for the preview link.
2. Tap **😍 אהבתי!**. Within a minute or two (the print files take a moment) you get the 🔧 request and the two buttons.
3. Tap **⚠️ יש בעיה**, type e.g. "בדיקה: אפשר להחליף את תמונה 5?" → you get it back as a customer message with **✏️ לשנות משהו**.
4. Type something as the customer, e.g. "תודה!" → it comes back to you as 🔧 with **💬 לענות** / **✅ לאשר**.
5. Tap **✅ לאשר** → the "ready for printing" message, and a 🔧 message with the print files' place.
6. Type **אישורים** → "no albums waiting" (all approved).

To see what happened: `grep -i "owner\|approved" ~/Library/Logs/pashut-book/bot.log | tail -10`

## Good to know

- **The 24-hour window, for you:** if you haven't written anything to the bot for 24 hours, WhatsApp silently drops the request (the log says "hasn't written to the bot for 24 hours"). Just type **אישורים** to the bot: every album still waiting comes again. While you test daily this won't happen. Later (task 0.4, the real number) we can add a "template" message (a pre-approved message that can be sent any time; costs a few agorot each) if this becomes annoying.
- **The 24-hour window, for the customer:** the "approved" message and your typed messages reach the customer only within 24 hours of their last message. So approve within a day of their "love it". If it's later, the bot log says it wasn't delivered. Task 3.2 (payment) will need the same care.
- **The print files** are made again for every request, from exactly what the customer saw: `output/albums/<order>/print-pages.pdf` and `print-cover.pdf`. The print rules are still placeholders until the printer is chosen (S.2). 🔒 Never send them to the customer.
- **Where it's kept:** in the order's notes in Supabase (`owner_check` = waiting for you, `approved`, `owner_problem`), so a bot restart doesn't lose it. No database change was needed.
- **No owner number** in `.env` → the bot works as before, and the log reminds you to add it.
- **The words** are in `server/texts/he.json` (`owner_…`, `team_message`, `sent_to_team`, `owner_approved_customer`).
- **Code:** `server/owner_approval.py`; tests in `tests/test_owner_approval.py`.
